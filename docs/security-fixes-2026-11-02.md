# InoceanMessaging 0.2.2 安全修复验证

日期：2026-11-02（America/Vancouver）。范围：审查报告第 1、2 项；第 3 项数据保留策略未改变。

## 修复

1. 用 DAL PreWriteValidation/PostWriteValidation 取代事务提交后的成功回调。客户订阅字段、consent 和 suppression 共用数据库连接与写入事务，失败全部回滚。客户同意记录新增 customer_id 和索引，退订可定位历史号码哈希及本次修改前号码。无法解析任何授权号码时明确返回错误，不能假报退订成功。升级前既有不一致需要按原始证据核对，迁移不自动推断历史授权归属。
2. 新任务持销售渠道行锁检查入队速率与 queued/sending 容量，再插入任务。默认 enqueuePerMinute=120、maxPending=1000，可配置范围 1–10000。超限返回 429、Retry-After: 60；不入库、不派发；幂等重放不占新额度。增加 (scope_id,status) 索引并复用 (scope_id,created_at) 索引，查询有 LIMIT，不统计完整历史表。

## 验证

在 maginut-app 的 PHP 环境中执行，数据库为独立临时 MySQL 8.0 容器 ino-messaging-security-test 中的 ino_messaging_test；供应商全部使用 MockHttpClient。未发送真实短信、未对业务库运行插件更新或迁移。

- tests/security.php：209 项累计回归及安全检查通过（含原 170 项）。
- 真实 Shopware DAL gateway：同步后的故障与 consent INSERT 触发器故障均回滚客户字段及授权记录。
- 无效当前号码仍按历史授权号码退订；同批更新地址与退订覆盖旧、新号码；仅号码发送不能绕过退订。
- 无法恢复旧授权身份时返回错误且客户字段不产生假成功。
- 入队满载返回 429；无额外记录与派发；幂等请求正常重放；不同渠道容量隔离；滚动窗口过后恢复。
- 6 个独立进程竞争 2 个积压名额，最终恰好 2 条；容量充足时并发每分钟限额同样只能新增 2 条。
- 迁移重复执行通过，复合索引可用于积压查询。
- tests/validate.php：配置 XSD、PHP DI、OpenAPI、插件元数据检查通过；PHP 源码语法检查通过。

没有进行生产负载压测，不将索引与并发正确性检查解释为性能基准；没有执行正式 Shopware 6.8 运行验证。
